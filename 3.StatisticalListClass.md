# Statistical Lists Overview

Statistical lists function similarly to extended global variables (key-value pairs). They offer high-speed reading (via cache) and persistent storage (writing to the database). The architecture follows a modern data access flow: **User (Script) -> High-speed Cache -> Database**.

When used, the system creates a table named: `cq_dataList`.

### Key Features:
* **Storage:** Each record (row) can store 32 different data points (`v1` to `v32`) for a single user (UID).
* **Usage Examples:** Tracking monster kills, total damage dealt, PvP kills, etc.
* **Ranking:** Supports sorting specific data types across all UIDs to generate rankings.
* **Efficiency:** Extremely efficient for reading. However, writing to the database takes time (approx. 5,000 operations per second).
* **Best Practice:** Avoid calling write functions too frequently (e.g., don't trigger on every attack). Instead, use lower-frequency events like NPC interactions or specific milestones.
* **Maintenance:** If you clear the main user database, you must also clear the `cq_dataList` table.

# Statistical List - Read Value

*Requires a USER object (Version 018.019 and above).*
*Example:* `sys_listRead %user_id 1`

* **Parameter 1:** UID. Usually `%user_id` to link data to the current player.
* **Parameter 2:** Index. The specific data slot to read (1–32).
* **Return Value:**
  * **Successful:** Jumps to `id_next`. Result stored in `%iter_var_str9`.
  * **Unsuccessful:** Jumps to `id_nextFail`.

## Example

| id | id_next | id_nextfail | type | data | param |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 100000100 | 100000101 | 100000102 | 2003 | 0 | `sys_listRead %user_id 1` |
| 100000101 | 0 | 0 | 126 | 0 | `Read value: %iter_var_str9` |
| 100000102 | 0 | 0 | 126 | 0 | `Read failed!` |

# Statistical List - Write Value

*No object required (Version 018.019 and above).*
*Example:* `sys_listWrite %user_id 1 888`

* **Parameter 1:** UID. Usually `%user_id`.
* **Parameter 2:** Index. The data slot to write to (1–32).
* **Parameter 3:** Value. The data to be written.
* **Parameter 4 (Optional):** Write to Database.
  * `1` = Write to database (Default).
  * `0` = Cache only (Use for high-frequency updates to improve performance).
* **Return Value:** Always succeeds.

## Example

| id | id_next | id_nextfail | type | data | param |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 100000100 | 0 | 0 | 2003 | 0 | `sys_listWrite %user_id 1 888` |

# Statistical List - Sorting

*Requires a USER object (Version 018.019 and above).*
*Example:* `sys_listSort 1 1`

* **Parameter 1:** Index. The data slot (1–32) to sort by.
* **Parameter 2:** Rank Number (N). Retrieves the UID of the player at the Nth position.
  * *Note: If there are only 3 players and you ask for rank 4, the script will fail (jumps to `id_nextFail`).*
* **Parameter 3 (Optional):** Sort Type.
  * `1` = Descending (Highest to Lowest) [Default].
  * `0` = Ascending (Lowest to Highest).
* **Return Value:**
  * **Successful:** Jumps to `id_next`. The **UID** of the ranked player is stored in `%iter_var_str9`.
  * **Unsuccessful:** Jumps to `id_nextFail`.

## Example

| id | id_next | id_nextfail | type | data | param |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 100000100 | 100000101 | 100000102 | 2003 | 0 | `sys_listSort 1 1` |
| 100000101 | 100000103 | 0 | 1010 | 2005 | `UID found: %iter_var_str9` |
| 100000102 | 0 | 0 | 126 | 0 | `Failed to read ranking data!` |
| 100000103 | 100000105 | 100000104 | 2003 | 0 | `sys_listRead %iter_var_str9 1` |
| 100000104 | 0 | 0 | 126 | 0 | `Failed to read value!` |
| 100000105 | 0 | 0 | 1010 | 2005 | `Ranking value is: %iter_var_str9` |

# Statistical List - Reset (Clear)

*No object required (Version 018.019 and above).*
*Example:* `sys_listClear 1`

* **Parameter 1:** Index. The data slot (1–32) to reset to zero for **all users**.
* **Warning:** This updates the database in real-time and is irreversible!
* **Return Value:** Always succeeds.

## Example

| id | id_next | id_nextfail | type | data | param |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 100000100 | 0 | 0 | 2003 | 0 | `sys_listClear 1` |

# Statistical List - Query Rank

*Requires a USER object (Version 018.020 and above).*
*Example:* `sys_listQueryRanking 1 %user_id`

* **Parameter 1:** Index. The data slot (1–32) to use for sorting.
* **Parameter 2:** UID. The specific player whose rank you want to find.
* **Parameter 3 (Optional):** Sort Type.
  * `1` = Descending [Default].
  * `0` = Ascending.
* **Return Value:**
  * **Successful:** Jumps to `id_next`. The **Rank Number** is stored in `%iter_var_str9`.
  * **Unsuccessful:** Jumps to `id_nextFail` (e.g., if the UID has no data in the list).

## Example

| id | id_next | id_nextfail | type | data | param |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 100000100 | 100000101 | 100000102 | 2003 | 0 | `sys_listQueryRanking 1 %user_id` |
| 100000101 | 0 | 0 | 1010 | 126 | `UID: %user_id is ranked #%iter_var_str9` |
| 100000102 | 0 | 0 | 1010 | 126 | `UID: %user_id has no ranking.` |
