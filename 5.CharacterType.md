# Check if Character Exists

*Example:* `sys_findName Jasmine`

* **Parameter 1:** The name of the player you want to check.
* **Return Value:**
  * **Character exists:** Executes `id_next`.
  * **Character does not exist:** Executes `id_nextFail`.

## Example

| id | id_next | id_nextfail | type | data | param |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 100000100 | 100000101 | 100000102 | 2003 | 0 | `sys_findName Jasmine` |

# Query Specific Target Info

*Requires a USER object.*
*Example:* `sys_findInfo 412252`

* **Parameter 1:** The Name or ID of the character/target (Player, NPC, or Monster).
* **Return Value:**
  * **Successful:** Executes `id_next`. Data is stored in the following variables:
    * `%iter_var_str9` = Target Name
    * `%iter_var_str8` = Target Map ID
    * `%iter_var_str7` = Target X Coordinate
    * `%iter_var_str6` = Target Y Coordinate
    * `%iter_var_str5` = Target Type (v016+; used to distinguish main/sub characters)
    * `%iter_var_str3` = Target ID
  * **Unsuccessful:** Executes `id_nextFail`.

# Character Rebirth (Reincarnation)

*Requires a USER object.*
*Example:* `sys_rebirth`

* **Return Value:**
  * **Successful:** Executes `id_next`.
  * **Unsuccessful:** Executes `id_nextFail`.
* **Effect:**
  * Character level drops to Level 1.
  * HP, Attack, Magic Attack, and Dodge values from the time of rebirth are preserved and increased by 100% (doubled).
  * With every level gained after rebirth, the attributes from the previous life are added/stacked. More rebirths = significantly stronger attributes.
* **Side Effects:**
  * **Level Contempt:** You will deal very low damage to monsters with a higher level than yours. This effect disappears as you level up.
  * **Short-term reduction:** Level and combat power are temporarily reduced, but will surpass previous limits as you re-level.
* **Version Note (v015+):** Dodge attribute no longer stacks/increases by 100%; other attributes still stack as normal.
* **Database Maintenance:** If clearing user data, the `cq_rebirthex` table must also be cleared as it manages this system.

# Pull Target to Self

*Requires a USER object. Forcefully teleports a target to your current location.*
*Example:* `sys_pullTarget Jasmine 100000101`

* **Parameter 1:** The name of the character to be pulled (e.g., Jasmine).
* **Parameter 2 (Optional):** Script ID. The pulled target will execute this script upon arrival.
* **Callback Variables (for the target):**
  * `%iter_var_str9` = Name of the player who pulled them.
  * `%iter_var_str8` = Level of the player who pulled them.
  * `%iter_var_str7` = Combat power of the player who pulled them.
* **Return Value:**
  * **Successful:** Executes `id_next`.
  * **Unsuccessful:** Executes `id_nextFail`.

---

# Push (Teleport) Self to Target

*Requires a USER object. Forcefully teleports yourself to the target's location.*
*Example:* `sys_pushTarget Jasmine 100000101`

* **Parameter 1:** The name of the target character to track/teleport to (e.g., Jasmine).
* **Parameter 2 (Optional):** Script ID. The target being tracked will execute this script when you arrive.
* **Callback Variables (for the target):**
  * `%iter_var_str9` = Name of the player tracking them.
  * `%iter_var_str8` = Level of the player tracking them.
  * `%iter_var_str7` = Combat power of the player tracking them.
* **Return Value:**
  * **Successful:** Executes `id_next`.
  * **Unsuccessful:** Executes `id_nextFail`.

# Suicide or Kill Others

*Forcefully kills yourself or a specified target.*
*Example (Suicide):* `sys_kill`
*Example (Kill Target):* `sys_kill Jasmine`
*Example (Kill with Notify):* `sys_kill Jasmine 100000101`

* **Parameter 1 (Optional):** The name of the character to kill. If left blank, you will kill yourself.
* **Parameter 2 (Optional):** Script ID. The target killed by this script will execute this script ID.
* **Callback Variables (for the target):**
  * `%iter_var_str9` = The name of the killer.
* **Return Value:**
  * **Successful:** Executes `id_next`.
  * **Unsuccessful:** Executes `id_nextFail`.

# Search Objects

*Requires a USER object.*
*Example:* `sys_queryObj 300 400 18 2`

* **Parameter 1:** Center X coordinate (Usually player's X).
* **Parameter 2:** Center Y coordinate (Usually player's Y).
* **Parameter 3:** Range (Usually `18` for full screen visibility).
* **Parameter 4:** Object Type (Values can be added together, e.g., Player + Monster = `3`).
    * `1`: Players
    * `2`: Monsters
    * `4`: Eudemons / Pets
    * `8`: NPCs
    * `16`: Summons
    * `31`: All objects (v017+)
* **Return Value:**
    * **Successful:** Executes `id_next`. Object IDs are stored in `%iter_var_str9` through `%iter_var_str3`.
    * **Unsuccessful:** Executes `id_nextFail`.
* **Note:** Use `sys_findInfo` with the returned IDs to get detailed information about the objects.

## Example

| id | id_next | id_nextfail | type | data | param |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 100000100 | 100000101 | 0 | 2003 | 0 | `sys_queryObj %user_map_x %user_map_y 18 2` |
| 100000101 | 0 | 0 | 2003 | 0 | `sys_magicAttack 3000 %iter_var_str9` |

# Add/Set Status BUFF

*Requires a USER object (Version 017.009 and above).*
*Example:* `sys_addStatus 158 30100 15 0`

* **Parameter 1:** Status Type ID (Refer to the Status ID Table below).
* **Parameter 2:** Status Value.
    * Values above `30,000`: Represents a percentage growth (e.g., 30100 = +100%).
    * Values below `30,000`: Represents an actual value growth.
    * Negative values: Represents a decrease/negative growth.
* **Parameter 3:** Duration. The time the status remains active, measured in **seconds**.
* **Parameter 4 (Optional):** Cycle/Frequency. Number of times the duration repeats. Usually set to `0` for one-time duration.
* **Return Value:** Always succeeds.

# Lottery

*Requires a USER object (v017.009 and above).*
*Example:* `sys_lottery 1`

* **Parameter 1:** Box Type
    * `1`: Holy Angel Box
    * `2`: 12-Star Box
    * `3`: 8-Star Box
    * `4`: EXP Ball Box
    * `5`: Rose Box
* **Return Value:** Always succeeds.
* **Note:** The system does NOT check inventory space. The script must manually verify if the player has enough empty slots before executing.

# Player Uses Item

*Requires a USER object.*
*Example:* `sys_useItem 111000 1 1`

* **Parameter 1:** Item ID.
* **Parameter 2:** Usage Position. (Use `0` for non-equipment items; for equipment, specify the wear slot).
